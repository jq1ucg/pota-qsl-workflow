smarthamlog_lotw_upload.py v1.7.0

Smart HAMLOG の ADIF を LoTW へ送る

Smart HAMLOG が出力した ADIF を整形し、TQSL の CLI で署名して LoTW へアップロードします。POTA 運用(JA)の QSO を、運用エリア(/0 /1 …)ごとに送る用途を想定しています。

必要なもの 基本の流れ 動作モード 使い方の例 オプション一覧 自動で行う整形 POTA-REF.csv 出力と終了コード トラブル対処 既知の制限

必要なもの

項目内容
PythonPython 3。標準ライブラリのみで動き、追加インストールは不要です。
TQSLインストール済みで、証明書(JQ1UCG/0 など)と Station Location を登録してあること。
polo-lotw-fill.py本スクリプトと同じフォルダに置きます(関数を読み込んで使います)。
POTA-REF.csv公園 REF から県・市郡区・JCC を引く対応表。-p で指定します。
Station Location既定では STATION_CALLSIGN の末尾 /n から POTA-nAREA を使います(JQ1UCG/0 → POTA-0AREA)。

基本の流れ

python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output --upload
  1. Smart HAMLOG の ADIF(複数可)を読み込み、整形する
  2. STATION_CALLSIGN ごとに output/…-JQ1UCG-0_lotw.adif のように書き出す
  3. TQSL で署名し、LoTW へアップロードする

何も付けずに実行すると、整形とファイル出力だけを行い、送信しません(dry-run)。実行予定の TQSL コマンドが表示されるので、確認してから --upload を付けてください。

動作モード

(指定なし)整形・出力のみ。TQSL コマンドを表示します(dry-run)。
--sign-onlyTQSL で署名して .tq8 を作るだけ。送信はしません。
--uploadTQSL で署名して LoTW へアップロードします。
署名だけでも「署名済み」になります --sign-only で署名したQSOは、TQSL が署名済みとして記録します。その後の --upload は「アップロードすべきQSOがない(終了コード8)」になります。初回から送るなら --sign-only を挟まず --upload を直接使ってください。署名だけ試した後で送るときは --action all を付けます。

使い方の例

内容を確認する(送信しない)

python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output

output/ の *_lotw.adif を開き、MY_STATE と MY_CNTY を確認します。

送信する

python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output --upload

署名済みのQSOを含めて再送する

python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output --upload --action all

LoTW 側で重複は無視されます。

証明書にパスワードがある場合

TQSL_PASS='パスワード' python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output --upload --password-env TQSL_PASS

パスワードはコマンドラインに直接書かず、環境変数で渡します。

日付で絞る

python3 smarthamlog_lotw_upload.py -p POTA-REF.csv ./adif-in/*.adi -o output --upload --start-date 20261107 --end-date 20261109

自動で行う整形

症状対処
公園番号が MY_SIG_INFO(MY_SIG=POTA)に入っているMY_POTA_REF を補完します。
MY_STATE / MY_CNTY が無いPOTA-REF.csv と突合して付与します(09 と 0908)。
FREQ が不正(例: 7.005.5)7.0055 に修正します。直せない値や BAND と矛盾する値は削除します。
同じ公園が複数エリアに登録されている(例: JP-0012)/n サフィックスと CSV のエリア列で行を選びます。
QSO の順序がばらばらQSO_DATE → TIME_ON 順に並べます。
STATION_CALLSIGN が複数ある局ごとにファイルを分け、別々に署名・送信します。
相手局の SIG / SIG_INFO(P2P)そのまま残します(LoTW 側では無視されます)。

時刻は UTC として扱います(Smart HAMLOG の出力が UTC のため)。

POTA-REF.csv の書き方

POTA-REF.csv
JARLエリア番号,公園REF番号,JP都道府県名,都道府県名+市区/郡名,JCC/JCG/AJA
0,JP-0012,JP-NN(長野県),長野県小諸市,JCC0908
1,JP-0012,JP-GM(群馬県),群馬県安中市,JCC1611
  • エリア列は、運用した場所の JARL エリア(/0、/1 など)です。同じ公園でもエリアが違えば別の行にします。
  • JCC の数字部分から、MY_STATE(先頭2桁)と MY_CNTY(数字全体)が決まります。
  • JCG 末尾の英字(例: 09015C)は載せません。TQSL の選択肢に無いためです。
  • 新しい公園は build_pota_ref_csv.py で追加できます。自動の値が実際の運用地と違う場合は、手で直してください。

出力ファイルと終了コード

ファイル内容
YYYYMMDD-JQ1UCG-0_lotw.adif整形後の ADIF(局ごと)。
YYYYMMDD-JQ1UCG-0_lotw.tq8署名済みファイル(--sign-only のとき)。
YYYYMMDD-JQ1UCG-0_lotw.tqsl.logTQSL の実行ログ(コマンド、終了コード、出力)。
終了コード意味
0正常
1入力・整形エラー
2TQSL の実行エラー(アップロード失敗を含む)
3TQSL が署名対象QSOを0件と判断(重複または期間外。TQSL の終了コードは 8)

トラブル対処

症状原因と対処
署名対象QSOが0件(終了コード3)重複(署名済み)か期間外です。画面に出る TQSL の出力を確認します。重複なら --action all を付けます。期間外なら、TQSL で証明書の QSO 開始/終了日を確認します。
「局の所在地は QSO データの詳細と一致していない」--location-mismatch update(既定)で解消します。古い TQSL で -f が使えない場合は none にして、公園ごとに Station Location を用意します。
「'US County State' の値として '09' ... 正しくありません」MY_CNTY が 09,0908 の形式になっています。--cnty-format plain(既定)を使います。
「TQSLの選択肢に無い市郡区」の警告POTA-REF.csv の JCC が TQSL の選択肢にありません。TQSL の config.xml で値を確認して CSV を直します。
公園REF未突合の警告POTA-REF.csv に公園がありません。build_pota_ref_csv.py で追加します。
複数県にまたがる公園の警告-c JP-0209:2 のように、CSV 内で何番目の行かを指定します。
TQSL が見つからない--tqsl /usr/local/bin/tqsl のようにパスを指定します(Windows は tqsl.exe)。
D-STAR が受理されないTQSL の設定データを更新します。それでも通らなければ --dv-mode dstar(または fm)を試します。
実機での確認結果 TQSL 2.8.6(Linux)で、329QSO(JQ1UCG/0 が 247件、/1 が 82件)の署名とアップロードが終了コード 0 で完了しています。

既知の制限・未確認事項

  • LoTW 上で D-STAR がどのモード区分(PHONE / DATA)に分類されるかは未確認です。
  • 動作確認は TQSL 2.8.6 で行いました。他のバージョンでは -f や -a の挙動が違う可能性があります。
  • 既存の polo-lotw-fill.py は、今も MY_CNTY を 09,0908(カンマ付き)で出力します。TQSL 2.8.6 ではこの形式がエラーになるため、その出力を TQSL へ直接渡す場合は再確認してください。
  • 署名とアップロードの結果は TQSL 側のログが正です。エラー時は *.tqsl.log を確認してください。
